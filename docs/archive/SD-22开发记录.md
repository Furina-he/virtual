## 1. 必须先解决的电气问题

当前《原型选型说明》的 555 应用板实际位于 **§5.4**，不是 §5.3。板面为 264 x 184 mm，共 36 个插孔；所有原有插孔 ID、顺序、坐标与固定元件参数均保留。

正式参数为 5 V，RA1=10 kΩ、RB1=150 kΩ、C1=4.7 µF；RA2=RB2=10 kΩ、C2=47 nF；C3=C4=10 nF、R5=10 kΩ、C5=100 µF，LS1 为 8 Ω / 0.5 W。旧 `tests/golden/fixtures/sd22.ts` 是不同参数的音频原型，不能替换它的值。

真实 ngspice 的原型复核发现：

- 救护车：IC1 OUT 经 R5 接 IC2 CV，低频重复振荡约 0.98909 Hz，IC2 CV 出现约 2.500625 V / 3.325006 V 两个平台。
- 消防车：IC1 TH 经 R5 接 IC2 CV，4 s 内 IC1 OUT 为 0 V、没有低频上升沿；TH 约为 3.061648815 V，IC2 CV 约为 3.265412196 V，输出保持单一音调而非渐变。

NE555 的 CV 端含真实的 5 kΩ + 5 kΩ + 5 kΩ 分压链，其戴维南等效为 3.333 V / 3.333 kΩ。消防车接法令 C1 通过 13.333 kΩ 连到这个源；即使放电管导通，RB1 为 150 kΩ，放电平衡点仍约 3.06 V，高于 IC1 的低触发阈值 1.667 V。不是调小仿真步长或补公共接口能解决的问题。

原始复核记录：`build/sd22-project-prototype-review.json`。记录来自真实模块电路和现有 NE555 模型，不是预录波形。

首阶段提出高输入阻抗缓冲修订时未实施；本次用户已明确批准并引入独立 TLV9001IDBVR 板，指南、BOM、原创图、参考网络和金标准已同步。原型 TH 直连造成停振的证据继续保留，不将它描述为工作正常，不伪造 CV 输入阻抗。

### 2.1 本地模型依赖解析

现有 `practice-content.ts` 只导入模块 `.cir`，直接传给纯 TS 拼装器；NE555 的标准模型位于 `content/models/spice/timers.lib`。本分支按主会话的命名库草案使用 `.include "timers.lib"`，不依赖工作目录或安装目录在 ngspice 中碰巧可读。声明放在本模块 `.ends` 后，展开后首先出现的 `.subckt` 仍为 36 端口的挂箱，而非库中的 NE555。

最小改动：内容加载层将明确声明的命名本地模型库解析、去重并内联后，仍经现有 `moduleNetlist(module): string` 返回文本。命名库映射限定到随包 `content/models/spice/` 的构建期本地内容；拒绝路径表达式、越界、外网、未声明文件和循环引用。不得向纯 TS `src/domain/` 引入文件系统或 Electron。开发版与安装版必须用同一内联结果。不要求主会话放宽草案的路径白名单。

### 2.2 自激电路与真实时间策略

当前 `buildMeasurementPlan` 只有接入示波器、交流表或有源信号发生器时才选择瞬态分析；同时只要有示波器就切到 `window` 节奏。需要一个内容驱动的自激模块分析声明，例如：

```ts
Module.simulation?: {
  kind: 'tran'
  maxStep: number
  pacing: 'realtime' | 'window'
}
```

合并规则：任一上电自激模块要求瞬态时选择连续 `tran`；最大步长取模块与仪表约束的最小值。任一执行器/扬声器要求真实时间时，现有 `setPacing` 必须为 `{ type: 'setPacing', mode: 'realtime' }`，不能被示波器时基覆盖。正式 SD-22 的真实 ngspice 步长复核表明：20 µs 的载频误差约 4.285%~5.725%，10 µs 仍约 1.580%~1.733%，5 µs 部分超过 1%；2 µs 时为 0.151%~0.606%。误差按含 RA 分压/有限 DIS 导通电阻的独立 RC 方程校核，详见电路审核。因此保留 <=1% 金标准时，模块需要 `maxStep <= 2e-6`，1 µs 可作为精度余量，不能沿用旧音频原型采样参数或放宽阈值。

这不是实时性能结论。精细步长的求解速度还须单独复核；如果无法按真实时间求解，主会话需先确认符合 SIM-11/13 的通用双节奏方案，不能只通过合成把错误的调制节奏隐藏。专属步长报告为 `build/sd22-step-review.json`。

只改示波器 V/div、位置、触发和冻结不重新起振；改时基也不能使低频调制或声音跳过墙钟时间。断电、项目切换和重置停止旧会话及旧声音，不能通过示波器另起一个加速的执行器会话。

### 2.3 扬声器差分探针与声音生命周期

原板实例为 `timer1`，扬声器为 `LS1`。现有字段可以声明：

```json
{ "id": "LS1", "kind": "speaker", "probe": "v(SPK_P,SPK_N)" }
```

`probe` 中的节点是模块**局部插孔 ID**，不是 ngspice 的固定节点名。内容层必须验证两个插孔存在；计划层按当前接线生成：

```ts
{
  id: 'speaker:timer1:LS1',
  kind: 'v',
  node: assembled.nodeOf['timer1.SPK_P'],
  nodeRef: assembled.nodeOf['timer1.SPK_N']
}
```

建议 `MeasurementPlan.speakers` 保存实例、指示器与探针 ID，公共运行时只有一个声音生产者。上电后的每个真实采样块经 `SimClient.onSamples(probeId, listener)` 同步进入既有 `SimAudioOutput.feed(samples,t0,dt)`，使用已选的 `synth` 模式和真实 `1/dt`，默认满幅 5 V。不得读取固定音频、参考电路输出或预录波形；采样和基频追踪不进入 React state。

音频对象创建是异步的：检查会话修订号，避免已断电/重置后完成的创建重新发声；取消订阅、停止旧对象、关闭或复用音频上下文须明确且可重复调用。浮动仪表窗口只读同一测量流，不重复播放声音。初始化失败应报告中文状态而非冒充正在发声。

### 2.5 示波器真实测量与任务记录

当前 `captureMeasurePoint` 明确拒绝 `waveform`，任务来源列表也只列电表。示波器已有真实 `max/min/vpp/mean/frequency/period`，应经公共快照暴露当前通道的低频摘要与接线证据，而不是把内部探针或理论值记入数据表。

最小扩展建议：波形测量量支持 `mean/min/max/vpp/frequency/period`，在测量点或数据列显式选定；期望区间使用相同语义。单位分别为 V、Hz、s，频率和周期不因表线反接改变；Vpp 非负。波形均值和极值使用 DC 耦合，反接时均值变号、极值交换并变号。已有电压/电流 `value` 保持当前有符号读数行为，兼容 DG-05，不把波形 `value` 默认为未知标量。

快照必须来自当前已发布的仿真修订、真实已接线的示波器通道；缺地、关闭、非有限值或旧会话不准记录。频率、周期以及明确要求周期振荡的任务须有至少两个完整有效周期（至少三个上升沿）；静态 CV 平台、停振诊断的均值/极值只要求有界、稳定且当前的实际采样窗口，不要求周期性。快照保留通道来源 ID、修订号、步长、实际测量窗口和冻结采集身份；多仪表/多通道匹配时要求明确选择通道，不能只按仪表实例合并。测量步骤不能因为手填一行或只检测到插孔连通就完成。当前正式内容的电容极值、CV 平台和载频列均没有绑定尚未存在的波形 API；公共接口就绪后统一迁移，之前只允许手填真实示波器结果，不将填表当作测量完成证据。

另有公共窗口限制：自动测量当前只读最近 65,536 点，20 µs 步长时仅有 1.31072 s，不能稳定测出约 0.99 Hz；2 µs 时更只有 0.131072 s，连默认 262,144 点原始环形缓冲也只有 0.524288 s。需要有界的长周期证据/真实低频观测数据通道，或基于真实块的持续边沿统计；不能只把一次临时数组无限加大。不能通过改大低频数值、降低仿真保真度、加速时间或写入 React 高频状态来绕过。示波器长时基与高频音频共存也须在同一真实时间链路中验证。
