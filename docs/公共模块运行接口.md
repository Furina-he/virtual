## 1. 模块声明

```ts
ModuleControl = {
  id: string; param: string; kind: 'pot' | 'switch' | 'rotary' | 'resistorBox'
  label?: string; unit: string; default: number
  range?: [number, number]; step?: number
  steps?: number[]; stepLabels?: string[]
  targets?: { element: string; scale?: number; offset?: number; min?: number; values?: number[] }[]
}
Module.simulation?: {
  analysis: 'tran'; maxStep: number; pacing?: 'realtime' | 'window'
}
SpeakerIndicator = {
  id: string; kind: 'speaker'; between: [JackId, JackId]
  audio: { fullScale: number }
}
```

- 状态仍是 `controlValues['<实例>.<控件>']`，数值按内容范围和档位校验；`param` 必须对应子电路 `params:` 中的参数。`stepLabels` 与 `steps` 一一对应，非扬声器指示器仍兼容已有 `probe` 声明。
- 拼装器生成 `.param p_<安全实例>_<param>=值`，并通过子电路参数引用。电位器用参数电阻，开关用有限开/关电阻或受控开关，结构保持不变。不能通过开关动作增删元件。
- `simulation` 显式要求连续瞬态，`maxStep` 为最大采样步长；未声明仍沿用已有仪表驱动分析。声明但未指定节奏时默认实时。纯放大器可显式 `window`；低频状态模块必须声明 `realtime`。
- 扬声器 `between` 只接受本模块实际插孔，编译为固定探针 `indicator:<实例>:<指示器>`，通过节点映射测两端电压；不执行任意 probe 字符串。`audio.fullScale` 是电压到音频满幅的比例，生产输出统一复用已选定的 synth `SimAudioOutput`。

## 2. 运行中改参数

```ts
{ type: 'load', requestId?: string, ..., parameterTargets?: { param: string; elements: string[] }[] }
{ type: 'loaded', requestId?: string, vectors: string[] }
{ type: 'alter', requestId?: string, changes: { param: string; value: number; targets?: { element: string; value: number }[] }[] }
{ type: 'altered', requestId?: string, simTime: number, changes: { param: string; value: number; targets?: { element: string; value: number }[] }[] }
```

- 只有声明的模块参数值改变，并且接线、模块/仪表、故障、预检、探针、分析、步长与节奏都相同，才发送 `alter`。其它变化仍走完整载入，不将重启宣称为连续改参。
- 连续瞬态的控件必须声明 `targets`：每项是本模块的实际电阻元件名，线性换算 `max(min, value*scale+offset)`，或 `values` 按 `steps` 索引映射阻值。映射仅支持有限正电阻，不执行任意公式或猜测网表。拼装计划把它展开为 `r.x<安全实例>.<元件>`，载入声明允许的参数/元件集合，后续 `alter` 同时发送逻辑参数和已求值电阻目标。仿真核只更新载入时声明的目标，避免任意元件改写。
- ngspice 在 50 ms 片间隙直接 `alter` 已展开的电阻值，连续瞬态不执行 `reset`，之后 `bg_resume`；逻辑 `.param` 仅同步用于保存和重启恢复。直流工作点与既有未声明目标的旧接口保留原参数处理，但不声称其可保持被改支路储能状态。成功后回传 `altered`。IPC 返回只表示接收，不是参数生效。运行端使用请求序号确认，参数待生效期间禁止记录旧值，确认后还须有生效时刻以后的采样/读数。
- 保留会话序号、探针 ID、RingBuffer、RMS 窗口对象及采样/扬声器订阅；匹配的生效确认会清空 RMS 累积统计，并划定波形可记录的新采样边界，不能继续记录旧参数窗口。快速连续操作不能由旧确认恢复新参数的记录权限。参数失败必须可见并停止错误作业，不能仅写日志再继续假装成功。
- 追加的真实 RC 测试已否定“`alterparam + reset` 对被改支路也保留电容状态”：时间和块序号继续，但改支路的解析误差约 1.79 V，不能放宽原 0.02 V 阈值。采用直接电阻更新后重新验证被改支路 RC 的分段解析解、源绝对相位、块序号/时间和参数开关；不承诺任意模型参数、改变电容值或拓扑都可连续修改。
- 当前参数和节奏纳入重启恢复；仿真进程重启是新的采样会话，渲染端清理旧数据并恢复最新内容设置。
- 公共验证：被改支路 RC/绝对正弦相位、子电路电阻开关、工作点确认顺序和目标白名单的真实 ngspice 测试 4/4 通过；工作台已有直流挂箱开关的真实 E2E 1/1 通过且会话载入次数不增加。共享锁日志为 `build/module-parameters-golden-verified.log`、`build/codex-public-module-e2e.log`。MD-03 后续真实 RW/KCE 会话连续性和实际应用流程亦通过，证据见 `build/codex-md03-runtime-golden.log`、`build/codex-md03-e2e-verified.log`；这些仍不能替代独立 SD-22 项目的实际声音/流程验收。

## 3. 节奏与声音生命周期

- 任一模块要求实时，或存在扬声器，实时节奏优先于示波器窗口；波形仍从同一真实仿真缓冲读取。长时基不得加速低频事件或音频调制。
- 步长同时满足模块、信号周期、示波器和声音采样限制。模块/声音的硬上限不能被示波器每屏预算反向放宽。
- 主工作台只有一个声音生产者，弹出仪表窗口不重复发声。声音使用自己的 AudioContext，不破坏万用表通断蜂鸣。
- 每次实际载入生成唯一 `load.requestId`，原生网表载入完成后回传相同 `loaded.requestId`。新声音组可以预先准备，但 `{ ready, activate(), dispose() }` 只有准备完成且收到自身匹配的实际 `loaded` 后才订阅；不能把 IPC 接收成功或过期载入确认当作新会话边界。运行端同时等声音准备与实际载入，再发送 pacing/run；RMS 也拒收载入确认前的采样。协议的 ID 对旧调用可选，公共工作台始终关联自己的载入请求。
- 创建声音实例的每次异步等待后都核对作业/资源代号。断电、错误、重置、项目切换、重载和销毁时，先解除逐块订阅，再静音/停止并关闭捕获的旧 context；晚到的创建结果立即停止。真正的参数 alter 不重建音色追踪器。
- 原始提前订阅会将旧末片（如 t=10 s）先送入新追踪器，随后新 t=0 数据无法正常产生音调帧；现由实际载入门禁修复。重放同一请求 ID 的实际 `loaded`（如原生重启恢复）也释放旧追踪器、建立新时间基准；被替换的载入确认和晚到资源不能重新绑定。若重放发生在等待 pacing 应答期间，最终 run 前再次等待并核对当前声音组身份，不使用旧组 ready 起跑。真实原生 FIFO/旧末片/新时间和序号归零 2/2、公共消费/协议/音频与缓冲测试合计 48/48 通过，日志 `build/codex-public-load-boundary-final.log`；重放等待缺口回归先失败，再修复通过。此证据不替代 SD-22 合并后的实际声音流程。
- 不得增加预缓冲或放宽欠载阈值掩盖性能问题；既有 PCM A 历史观察项仍保留。
- SD-22独立分支首片门禁修订（2026-10-30）：连续瞬态第一次原生片未返回前，`probeValues`只是初始化的0，不能发布为真实`readings`。`sendReadings`现在要求当前载入的`readIdx>0`，首次实际取样后才发布；向量截断仍保留`readIdx=1`，合法0 V瞬态及真实0 V工作点不受影响。不通过值非零判断证据。新纯边界4项及真实RC/工作点3项先4失败/3通过，修后连同既有原生边界/会话共12/12；`build/initial-readings-20261030-{red,green}.log`。不修求解性能、不扩大原超时或实时门槛。

## 4. 示波器记录与教学计算

- 波形测量点使用 `quantity: 'mean' | 'vpp' | 'min' | 'max' | 'frequency' | 'period'`，默认 `vpp`。记录只从实际接线且有效的示波器通道取最新真实测量；GND 耦合、未接参考地、未就绪或旧参数数据不能作为测量证据。
- `mean/min/max` 使用 DC 耦合；反接时均值变号，极值交换并变号；Vpp/频率/周期保持非负。数值单位由测量量决定，不解析显示文本或注入理论值。
- 同一示波器的两个有效 DC 通道可作为 `CH1-CH2` 或 `CH2-CH1` 的同步差分记录来源；必须具有一致的采样步长、结束时刻和共同参考地，先逐点相减再测量，不把两次标量极值相减冒充时域差值。该能力仅用于记录实测差分，不宣称完成 INS-11 整套增强功能。测 VCE 时保持示波器地线接电路 GND，CH1 接 C、CH2 接 E；禁止为了省差分把实际接地地夹接 E 而短接发射极电阻。
- 同一通道对的正/反差分只是一个物理记录来源，自动匹配不会因此制造“多台仪表”歧义；独立通道或独立仪器都接到同一测量点时仍要求选择来源。
- 数据列可用 `captureSteps?: string[]` 限制当前阶段记录，防止空载和带载共用测量插孔时同时覆盖两个记录。步骤可用 `dataTable?: string` 指定关联表，引用由 schema 校验。
- 步骤可追加 `expects?: Expectation[]`（每项仍为 `measurePoint/min/max`，SI 单位、闭区间），与旧 `expect` 一起逐项检查同一个当前真实快照；同测点的多个范围取交集，不静默覆盖。条件引用纳入测点范围与记录后推进；缺省或空数组保持旧内容兼容。近期有效周期不代表整个极值/均值窗口已经稳态，阈值与平台教学步骤须声明对应实测范围。此门禁只约束步骤完成，不禁止记录真实 0 V 或手填、不把 `sanity` 提示改为评分，也不把理论值写入仿真或记录。
- 波形点可声明 `windowSec`（有限 `0 < seconds <= 16`）。调用 `currentMeasurementSnapshot(windowSeconds)` 会为实际连线通道提供同 `probe/window/revision` 的有界 stream 读数，带 `requestedWindowSec` 标记及其同窗 `statistics`。不会把声明窗挤进 65,536 点 scratch、扩原始 RingBuffer 或用周期/屏幕宽度猜测是否可用；实际覆盖、步长和结束时刻不匹配/不足，加载/alter/暂停后的历史不足、停止/单次冻结等均拒绝作为该请求窗证据。未声明窗口的旧读数选择保持原样。同探针同长度每次快照只取一个 LongWindow 结果；多点共享其窗口/统计来源。差分只有同一采样 grid、完整连续 raw 历史且不超 65,536 点才逐点计算并重算完整窗口 mean；长窗/数据缺口保留已接拓扑身份并明确不可用，不能相减两个独立包络极值。16 s/2048、raw 1 MiB 和 65,536 点 scratch 上限不变。
- 步骤可声明 `referenceNets?: string[][]`，完整替换该步骤的默认参考网络，不与默认网络合并、不沿用前一步隐藏状态；未声明时仍用 `Project.reference.nets`。重复归属、插孔格式和真实模块/仪表插孔引用由 schema 与 `content:lint` 共同检查。不同教学模式须在各自步骤明确声明完整网络，不能按项目编号放宽检查。
- 已有 `computed` 字段只允许同一行数值列、数值常量、括号与 `+ - * /` 的有限算式，不使用 `eval`、JS 函数或任意属性访问；缺测量、零分母或非法运算产生未完成值和明确提示。公式只处理记录，不驱动仿真。

### 有界长周期证据

- `SimClient.observation(probeId)` 为实际示波器采样建立 `LongWindow`：固定16 s / 2048时间槽，约112 KiB/通道，保存真实采样计数/均值/极值和逐原始样本边沿。原始RingBuffer仍262,144点/1 MiB，记录scratch仍65,536点；长时基不能按`屏幕秒数/rawStep`申请无限数组。
- 一个采样块按现有时间槽分段、局部累积统计后一次写槽，避免细步长时每个样本重复计算槽索引/写入所有数组；仍逐原始样本判沿，不抽样、不增大缓冲。这个减负措施不等于已查清或消除了历史原生采样停顿。
- 频率不从抽点或包络均值计算。逐原始样本经固定代际的中值/迟滞识别真实上升沿，最新两间隔须一致（1%），至少三个有效上升沿才提供频率/周期；随后只累计同一稳定连续段并限制在当前窗口内。停振、过期间隔、不完整窗口返回null而非虚构0 Hz。阈值实质变化、断采样、非有限值和步长变化清除周期证据；载频不会因128 Hz包络槽混叠成1 Hz。
- SD-22独立分支接续修复（2026-10-30）：从0 V充电的启动极值会令后续1.667–3.333 V周期无法跨过旧迟滞。现用有限标量追踪真实方向反转，反转幅度不得小于实际门槛迟滞；两次相反有效反转可重新校准不可达门槛并清旧代际。保留全部16 s历史/真实启动极值，不把包络当采样或造边沿。完整真实历史幅度收窄后释放过时校准，避免小振幅永久锁死；10 mV/100 Hz纹波不得抢占1 Hz证据。本分支纯单元LongWindow41/41、关联5文件100/100，红/绿证据`build/sd22-long-window-*.log`；不以此替代正式双555的ngspice或实时性能结论。
- `MeasurePoint.minCycles?: number`（整数≥2）可要求更多完整周期；频率/周期记录默认至少2周期。均值/极值/Vpp没有周期要求，静态平台可以记录；明确周期性测量的Vpp/极值点应声明minCycles。手填不能替代这些实时证据。
- 捕获保留`window:{start,end,rawStep,completeCycles,source:'raw'|'stream',revision,frozen}`。边界槽完整保留，窗口首边可能多保留不到7.8125 ms，start/end均如实标出实际采样覆盖；不得把包络槽间隔冒充求解步长。长观测最大16 s，超长周期不能通过无限扩容测得。
- 示波器长屏用≤2048点真实min/max包络绘制，2D/3D共用同一帧；自动模式为滚动观测。包络不伪造触发，超原始缓冲范围的常规/单次仍显示等待/待触发；短屏既有真实触发/单次冻结不变，停止/冻结身份明确，不能用冻结后新采样冒充记录。
- `loaded`释放旧观察句柄与映射；匹配`altered`清统计并保留既有订阅/原始缓冲，记录只用生效后窗口。公共真实ngspice及Electron验证同一实时2 µs流里的1 Hz、1025 Hz和差分声音，未加速调制、未减小保真度或放宽50 ms运行中长任务阈值。AudioContext首次初始化约0.46 s另记观察项，资源准备完成后才起跑；运行中与初始化性能不能混作同一验收。

### 本地模型边界

`moduleNetlist`只接受随包构建期命名库`.include "<name>.lib"`。不接受目录、绝对路径、网络地址、`.inc`或`.lib`旁路；拒绝未知依赖和循环引用。重复/传递依赖及跨模块的相同模型/子电路只保留一份，不同定义同名报错；模型许可证注释保留，领域代码不读取文件系统。开发与安装使用相同内联文本，不依赖ngspice工作目录。

## 5. Worktree 重测试互斥

同一仓库的 worktree 共享 Git common directory；即使当前只有一个工作树，也使用统一入口。全量测试、真实仿真金标准、Electron E2E、音频、性能和资产构建占用同一个验证锁：

```powershell
node tools/run-exclusive.ts test
node tools/run-exclusive.ts test:golden tests/golden/<本分支测试>.test.ts
node tools/run-exclusive.ts e2e
node tools/run-exclusive.ts e2e:only tests/e2e/<本分支测试>.spec.ts
node tools/run-exclusive.ts assets:build
```

锁文件位于 `<git-common-dir>/codex-coordination/heavy-test.lock`，记录 PID、任务、工作区和启动时间；已有占用时返回 75，并显示占用者，不自动删除。另一分支未引入脚本前不得同时直接跑重测试。正常退出释放自己持有的锁；异常终止留下的锁须确认原进程与子测试均结束后人工处理。类型、lint 和纯轻量单元测试可并行；资产目录的 manifest/许可证等生成输出最终统一合并与校验，不能以覆盖一方文件代替合并。

真实金标准在机器负载或默认多 worker 下可能撞到原测试超时；复验可用 `node tools/run-exclusive.ts test --maxWorkers=1` 串行运行，不增加测试超时或放宽物理误差门槛。正式性能测试仍应独占且保持既有测量方式/阈值，串行编排不是目标机性能通过的证据。

## 7. 默认关闭的原生分段诊断

## 8. 同窗平台测量契约

`Step.expects` 与旧 `expect` 共同形成显式实测范围的 AND 门禁。静态 CV 的 raw 记录在 2 µs/65536 点下仅覆盖约 0.131070 s；均值合格仍可含 1% 旧平台样本，因此不能证明完整平台。
