## 3. 核心数据模型

全部以 zod schema 定义在 `src/shared/schema/`，schema 是数据契约的唯一来源。下面是骨架，实现时补全字段。

### 3.1 模块（实训挂箱）`module.json`

```ts
Module = {
  id: string                    // "mod-dc-circuit"
  name: string
  model: string                 // GLB 路径
  netlist: string               // module.cir，.subckt 端口名 = jackId
  jacks: { id: string; label: string; kind: "banana4" | "pin" ; polarityHint?: "+" | "-" }[]
  controls: {                   // 台面可调件（BEN-08），对应 GLB 中 KNOB_/SW_ 锚点
    id: string; kind: "pot" | "switch" | "rotary" | "resistorBox"
    param: string               // 网表中的 .param 名

  }[]
  indicators: { id: string; kind: "led" | "lamp" | "segment7" | "motor" | "speaker"; probe: string }[]
  commonNets?: string[][]       // 板上同一铜箔网络的插孔组（如 U1- 与 E），接线检查按同一节点处理
  internalJumpers?: { id: string; kind: "jumper" | "currentSocket"; a: string; b: string }[]   // 短接帽始终接通；电流插座常闭，两端都接了导线（插入电流插头）时断开
```

### 3.4 电路状态（运行时，zustand + zundo）

```ts
CircuitState = {
  placedInstruments: { instanceId: string; instrumentId: string; slot: string; settings: Record<string, unknown> }[]
  wires: { id: string; a: JackRef; b: JackRef; color: WireColor; label?: string }[]   // JackRef = "<instanceId>.<jackId>"

  powered: boolean
  activeFault?: string

```

只有 `wires`、`placedInstruments`、`controlValues` 进入 zundo 撤销栈；`powered`、仿真结果不进。

T0.8/T0.9 继续开发补充（2026-10-28）：
- `Wire.slack?: number` 为外观布线路由参数，范围 0.02~0.4 m，缺省按 0.12 m 使用；含义是水平中点处相对端点连线的垂直下垂量，不是额外导线长度。它随 `wires` 一同进入 zundo；所有导线、控制值与放置状态共用该撤销栈，不另建手写历史数组。
- 运行中的待接线端点、悬停、选中、颜色选择、画质等 UI 状态不进入电路历史。增加、删除、清空、路线调整等图变更才形成历史记录，无效或无变化的操作不得制造记录。
- 本轮场景来源为 `content/bench/scene.json`（`src/shared/schema/scene.ts` 的 `BenchScene`），只作场景/接线开发样例，不能当作已经完成 T0.15 的项目指导书/实验配置。插孔全局 ID 稳定采用 `dc1.*`、`ins-dc-power.*`、`ins-dc-voltmeter.*`、`ins-dc-ammeter.*`、`meter1.*`、`scope1.*`、`generator1.*`，不再使用随预览顺序变化的实例编号；项目差异仍放内容数据，不在代码中按项目 ID 分支。
- `pnpm assets:lint` 现在检查实际 `scene.json`：资产 ID、唯一实例、插槽存在/类型/占用、相对实训台的世界变换、固定仪表内容 ID 与 `fixedSlot`；预览预算也按该文件中的放置实例计算，不再只统计制作目录的旧预览表。通用 `content:lint` 保持独立，任意内容测试目录不强制依赖工作区资产目录。
- 台式仪表在此样例中预置，仪表柜拖放留给 T0.11。`powered` 暂用于接线界面的上电/断电状态；当前带电增加、删除、清空、路线/标签调整及撤销重做均拒绝并提示先断电，不改变历史。它不等于已接通仪表测量/保护逻辑；“检查接线”仍待参考拓扑等内容和后续功能接入。

## 4. 进程与通信

### 4.1 进程职责

| 进程 | 职责 | 禁止 |
|------|------|------|
| main | 窗口、IPC 路由、文件读写、PDF、启动/重启 sim 进程、撮合 MessagePort | 执行仿真、阻塞 I/O |
| preload | `contextBridge` 暴露 `window.api`，参数用 zod 校验 | 暴露 `ipcRenderer` 原对象 |
| sim (utilityProcess) | 加载 ngspice、维护仿真会话、按时间片推进、推送采样 | 访问文件系统中 `content/` 以外的路径 |
| renderer | UI、3D、波形、领域逻辑调用 | Node API（`nodeIntegration: false`、`sandbox: true`） |

### 4.2 通道

| 通道 | 方向 | 机制 | 内容 |
|------|------|------|------|
| 控制通道 | renderer ↔ main ↔ sim | `ipcRenderer.invoke` / `utilityProcess.postMessage` | 载入网表、上电/断电、改参数、开始/暂停 |
| 数据通道 | sim → renderer 直连 | main 用 `MessageChannelMain` 创建一对端口，分别交给 sim 和 renderer | 采样块 `{t0, dt, channels: Float32Array[]}`（transfer）、读数快照（10 Hz） |
| 事件通道 | sim → renderer | 同数据通道 | 不收敛、短路、过流、模型错误 |

渲染端：每个探针一个 `Float32Array` 环形缓冲（`renderer/lib/ring-buffer.ts`），`OscilloscopeScreen` 与 3D 屏幕纹理在 rAF / `useFrame` 中读取。高频数据不进 React state；读数快照以 10 Hz 写入 zustand 的 `readings` 切片。

### 4.3 仿真会话协议

类型定义放在 `src/shared/ipc/sim.ts`，消息全部经 zod 校验。

```ts
// renderer → sim（经 main 转发的控制消息）
type SimCommand =
  | { type: "load"; netlist: string; probes: Probe[]; analysis: Analysis }
  | { type: "run" } | { type: "pause" } | { type: "stop" }
  | { type: "alter"; changes: { param: string; value: number }[] }   // 电位器、开关、档位、信号源参数
  | { type: "setPacing"; mode: "realtime" | "window"; windowSec?: number }

type Probe = { id: string; kind: "v" | "i"; node?: string; nodeRef?: string; source?: string }
type Analysis =
  | { kind: "op" }
  | { kind: "tran"; step: number; continuous: true }
  | { kind: "ac"; fStart: number; fStop: number; points: number }

// sim → renderer（数据端口直连）
type SimEvent =
  | { type: "loaded"; vectors: string[] }
  | { type: "op"; values: Record<string, number> }                    // probeId → 值
  | { type: "chunk"; t0: number; dt: number; data: Record<string, Float32Array> }
  | { type: "status"; state: "idle" | "running" | "paused" | "error"; simTime: number }
  | { type: "error"; code: "no-convergence" | "singular" | "model" | "crash"; message: string; detail?: string }
  | { type: "log"; line: string }
```

实现补充（T0.4）：`chunk` 带块序号 `seq`（每次 `loaded` 从 0 重新计）；新增 `readings` 事件承载 10 Hz 读数快照。Electron 的 `MessagePortMain` 只能转移端口、不能转移 ArrayBuffer，所以 sim→main 这一跳每块复制一次（约 8 KB），可接受。`contextBridge` 不能传 `MessagePort`，preload 用 `window.postMessage` 把端口交给页面，渲染端（含弹出窗口）用 `window.api.sim.requestPort()` 申请。

约定：`chunk` 中数组按 `transfer` 发送；一次 `load` 对应一个会话，新 `load` 自动结束旧会话；`error.message` 已是面向学员的中文提示（PRD 15.4），`detail` 为 ngspice 原文，只进日志页。

### 4.4 sim 进程崩溃

main 监听 `exit`，自动重启 sim 进程并重新下发当前网表（实测 0.6~0.7 s 恢复）；启动后 5 s 内连续崩溃 3 次则停止重启，避免坏网表死循环；渲染端状态栏显示"仿真已重启"。ngspice 内部错误通过回调转为事件，不抛到 JS 顶层。

## 5. 仿真

### 5.1 ngspice 集成

- 绑定的共享库函数：`ngSpice_Init`、`ngSpice_Circ`、`ngSpice_Command`、`ngSpice_running`、`ngGet_Vec_Info`、`ngSpice_AllVecs`，回调 `SendChar`、`SendStat`、`ControlledExit`、`SendData`、`BGThreadRunning`。
- ~~`SendData` 逐点回调累积成块~~（T0.4 实测否决）：逐点跨线程回调在 Electron 内只有约 2.7 万点/秒，20 μs 步长下仅 0.55 倍实时。改为**按 50 ms 时间片推进**：`stop when time > T` + `bg_resume`，每片结束后按偏移批量读取新增向量数据（`readVector(name, start)`），重采样到等间隔网格再发块；不受限时约 3 倍实时，时间片同时用于实时节奏控制。后台运行要出数据须注册 `SendInitData` 回调。`koffi.view` 在 Electron 内崩溃，不使用。
- 不能给 tran 设"无限长"终止时间：ngspice 按终止时间/步长预估内存，过大会使整个 DLL 退出。用 `.tran 10 1e6 0 <步长>`，实际步长由最大步长参数约束。
- 暂停、停止、重新载入、`alter` 都在时间片边界执行（最多晚 50 ms），不从 JS 线程调 `bg_halt`（可能与排队中的回调死锁，未验证）。
- 分发目录 `resources/ngspice/`，`spinit` 只加载 `analog.cm`、`digital.cm`、`spice2poly.cm`、`xtradev.cm`、`xtraevt.cm`；`table.cm` 为 GPLv2+，不分发（结论见 `resources/ngspice/LICENSE-NOTES.md`）。
- 共享库只通过环境变量 `SPICE_LIB_DIR` 找 `spinit`，加载 DLL 前由 `NgSpice.open(dir)` 设置；依赖的 `libomp140`、`sndfile`、`samplerate` 先于 `ngspice.dll` 预加载。官方 dll 包缺 `sndfile.dll`/`samplerate.dll`，取自同版本控制台包。
- 错误判定靠解析 ngspice 文本输出（Error/aborted 行）；`ControlledExit` 后 DLL 无法再初始化，只能重启 sim 进程（§4.4）。

### 5.2 网表拼装（`domain/circuit`）

1. 每个模块实例展开为 `X<instanceId> <端口节点...> <moduleSubckt>`，端口顺序 = module.json 中 `jacks` 顺序。
2. 每台仪表按当前档位由 `spiceTemplate` 生成等效电路（电压表 = 内阻 + 电压探针；电流表 = 内阻 + 0 V 电压源测流；电源 = 理想源 + 内阻 + 限流行为模型）。
3. 学员导线 + 模块内跳线用并查集合并插孔 → 节点名。接地参考：台面"地"插孔所在网络为节点 0；无地时自动加 1 GΩ 到地防浮空（SIM-12）。
4. 每个节点追加 1 TΩ 对地泄放电阻，避免未连接插孔导致矩阵奇异。**这两步是必做项，不能依赖 ngspice 报错**：T0.3 实测浮空电容、电流源灌电容、电感直跨电压源等情况 ngspice 经自动收敛辅助后会"成功"返回无意义数值，不报错。
5. 故障注入在此步改写网表（§8）。
6. 输出：网表文本 + 节点映射表（插孔 → 节点）+ 网络划分（供接线检查）+ 仪表实例后缀（拼探针向量名，如电流表 `vsense_<后缀>#branch`）。

补充约定（T0.5）：模块子电路端口顺序必须与 `jacks` 一致；同一铜箔网络上的插孔在子电路内用 1 μΩ 相连；控件写成全局 `.param p_<实例>_<参数>`，经子电路 `params:` 传入，便于运行中 `alterparam`；没接线的仪表不进网表；故障只改写目标实例的子电路副本。

这一层是纯函数，金标准测试覆盖。

### 5.3 分析类型选择

| 场景 | 分析 | 说明 |
|------|------|------|
| 只有直流源、直流仪表 | `.op` | 改参数后重跑，目标 ≤ 0.5 s（NFR-02） |
| 交流电表/功率表读数 | 短时 `.tran` 若干周期后取有效值 | 不用 `.ac`，因为含非线性负载（灯、日光灯）时 `.ac` 不对 |
| 扫频（谐振曲线、幅频） | 学员逐点改频率测量，每点 `.tran`；"曲线"页可选 `.ac` 快速预览 | 数据表须来自学员测量 |
| 示波器、数字电路、振荡器 | 连续分片 `.tran`（§5.4） | — |

### 5.4 连续运行与实时推进（SIM-06/11/13）

```text
上电 → 载入网表 → bg_run tran（步长 = 当前示波器时基决定，终止时间 = 很大）
      ↓ SendData 回调累积 → 每块推送
学员改参数 → 时间片间隙 alterparam p_<实例>_<参数>=v → reset（tran 时间、电容电压、XSPICE 状态均保留，读数 0.08~0.2 s 内变化）
学员改接线 → 断电提示（WIR-07）；若带电改线 → 重新拼网表、从当前节点电压作初值重跑
```

- 内存：不重启 tran。每读出 5 万点用 `let v=v[末点]` 截断当前 plot 的全部向量（原地换缓冲，tran 写入指针不变）；载入和 reset 后执行 `esave none`；每片调用 `ngSpice_Command(NULL)` 释放命令控制结构；向量用 memcpy 读进复用缓冲，不用 `koffi.decode`。首片前不得 `delete all`，否则 `.save` 失效。实测 10 分钟 77~82 MB 平稳（改前约 1 GB）。
- 节奏控制：sim 进程比较仿真时间与墙钟时间，仿真快于实时就暂停（数码管、1 Hz 秒脉冲、电机按真实时间走），落后墙钟超过 1 s 放弃追赶；示波器"运行"状态下按时间窗口仿真，`rate = max(1, windowSec/0.1 s)`，即每 100 ms 至少推进一个窗口，不设窗口则不限速。不需等待时用 setImmediate（Windows 上 setTimeout 粒度约 15 ms）。实测 1 Hz 计数 60 次误差 0.06%。
- 音频（SIM-13，P1）：**采用"提取基频和包络 + OscillatorNode 合成"**（T0.6 结论）。基频和包络每 10 ms 提取一次，PeriodicWave 音色每 0.5 s 按实测谐波更新。理由：SD-22 在 1/44100 s 步长下只有 1.35~1.48 倍实时（i5-12450H），单核 CPU 约 70%，基线机余量更小，低于实时就断音；逐点播放有混叠（谐波外能量 −4.5 dB，抗混叠参照 −20.6 dB），过采样后又跟不上实时。合成方案音高误差中位 0.1 音分，与机器速度无关。AudioWorklet 逐点播放的原型保留，示波器波形仍来自仿真。
- 不收敛：捕获 ngspice 错误 → 尝试 `.options gmin/reltol` 放宽一次 → 仍失败则状态栏"不收敛"并提示检查接线。

### 5.5 器件模型库（WP-MODEL）

- `content/models/spice/` 下按类别分文件：`diodes.lib`、`bjt.lib`、`fet.lib`、`thyristor.lib`、`opamp.lib`、`regulators.lib`、`ttl.lib`、`cmos.lib`、`timers.lib`（NE555）、`behavioral.lib`（白炽灯、日光灯、气敏、话筒、电池、电机、晶振行为模型）。
- 数字芯片：用 XSPICE 原语（`d_nand`、`d_dff`、`d_jkff`、`d_tristate` 等）+ `adc_bridge`/`dac_bridge` 组成子电路，引脚顺序与 DIP 封装一致，含 VCC/GND 引脚（VCC 或 GND 任一未接，芯片都不工作，贴近实物）。实现：输入以本片 GND 为参考判阈值，输出幅度取自 VCC−GND，时钟与锁存使能和"电源正常"信号相与。
- 自由振荡电路（555 多谐、环形振荡、SD-14 微分型单稳等）没有稳定的直流初始点，ngspice 求初值会不收敛。模型内部用上电延时（如 555 锁存在 t<1 ns 保持 0）处理；连续运行从不重启 tran，因此不需要统一的 `.ic`/`uic` 策略（T0.6 结论）。
- XSPICE `adc_bridge` 在 in_low~in_high 之间输出不定态，慢变输入停留其中会使锁存器进入不定态；比较器类模型取 `in_low = in_high`（NE555 已改）。
- 每个模型一个金标准用例（`tests/golden/models/`）：二极管 I-V 若干点、三极管 β、运放增益带宽、74 芯片真值表/功能表。
- 每个模型在文件头注明来源与许可证。

## 6. 接线检查（WIR-03、B1）

1. 从当前状态构建"被测电路网络"：去掉所有仪表的连线，把电流表位置视为短路（串入支路）、电压表视为开路，得到插孔分组。
2. 与 `reference.nets` 比较：两者都是插孔集合的划分，比较划分是否相同 → 天然支持等效接法。差异转换为可读提示："插孔 A3 应与 B1 相连""R2 与 R3 之间多了一根导线"。
3. 测量点检查：对 `measurePoints` 逐个看是否有相应仪表接在正确位置（电压表两端分别在 `between` 两个网络上；电流表串在 `branch` 中）。
4. 危险接法（WIR-06）独立于参考电路，上电前和仿真中都检查：电流表两端直接跨在电源两端、电源输出短路、超量程、电解电容反压。

实现补充（T0.13，`domain/wiring-check/`）：
- 划分同时计入模块 `commonNets`、短接帽和电流插座（两端都接了线视为插入电流插头、插座断开）；参考划分中电流表按短路处理，电流插座按接通处理。
- 参考拓扑与测量点里的插孔：固定仪表写 `<仪表id>.<插孔>`；台式仪表也按仪表 id 书写，检查时映射到台面上该仪表的实例。
- 叠插在测量仪表插孔上的两根导线在物理上是连通的，按连通处理。
- 极性接反只给警告（读数为负），不判测量点错误。
- 超量程、电解电容反压依赖仿真读数，放在仪表逻辑（T0.11）中判定。

## 7. 虚拟仪表（INS）

- `src/domain/instruments/` 只依赖 TypeScript 和共享 schema。`resolveInstrument` 将当前档位解析为 SI 量程、显示单位、内阻、分辨率、精度、极性和测量插孔；`readInstrument` 处理取整、确定性精度边界、反接负值、`OL.`、错档/断线、外部带电保护及通断蜂鸣；`rms` 只接受等间隔采样窗口。

T0.8/T0.9 本轮实现补充（2026-10-28）：
- 三档画质沿用本地 GLB/HDRI/字体，通过阴影、分辨率和渲染开销形成实际差异，切换不能改变电路图。开发期分别记录三档的分辨率/DPR、冷启动、实际渲染统计与连续相机操作时的帧率；静止 `demand` 场景停止绘制不算“无限 FPS”或基线性能通过。
- 当前档位实参：高/中/低贴图最大边长 2048/1536/1024 px，接触阴影分辨率 1024/512/关闭，DPR 范围分别 `[1, 2]`/`[1, 1.5]`/`[1, 1]`（前两档为设备 DPR 上限，不强制倍数）。每个实例拥有克隆材质/纹理，降采样和释放不修改 `useGLTF` 缓存的共享资源；画质保存在本地设置，不进入电路历史。
- 导线几何计算置于纯 TS 的 `src/domain/wiring/cord.ts`，不引用 React、Electron 或 Three.js。接口为 `cordPoints(a: [number, number, number], b: [number, number, number], sag: number, segments = 32)`，单位米，输出含精确两端点的 `segments + 1` 个样点。一般情况在端点 XZ 水平跨度所在的竖直平面中求真悬链线，重力朝 -Y；不以 Bezier 或“斜直线 + 对称 cosh”假代两端不同高的悬链线。
- 悬链线的下垂参数取端点连线水平中点到曲线的垂直距离，数值范围与 `Wire.slack` 一致；非退化跨度使用有界二分求解，近竖直/重合端点退化成确定性的侧向小环，保证有限坐标与精确接头。渲染端负责插头朝向、叠插分离和台面/地面限位；数学函数不假装执行碰撞或导线物理仿真。
- 实际求解以 `q = D / (2a)` 为未知量，满足 `sag = hypot(D * sinh(q) / q, deltaY) * tanh(q / 2) / 2`，其中 `D` 为 XZ 水平跨度、`a` 为悬链线尺度；消去水平偏移后求此单调标量方程，并保留不同高端点必需的 `sinh` 项。水平跨度小于 1 μm 时走侧向退化曲线；样本段数允许 2~512，非有限输入报错。22 个测试已覆盖端点、重力方向、不同高真悬链线解析对照、采样密度、竖直/重合和单位边界。
- `PatchCord3D` 按上述样点分段插值生成管线，不用会越出采样包围范围的平滑样条。插头按法线轴向叠插并侧向分离；导线在桌面/地面及途经面板正面作可视限位；PE 导线为黄绿双色。20 根以内逐根渲染，超过 20 根按颜色合批，选中导线单独高亮；这些属于可视几何策略，不是电路拓扑或物理仿真。
- 鼠标拖出/释放到合法插孔才创建导线；Esc、无效区域释放、窗口失焦、取消或重复连接拒绝不得遗留草稿。键盘/接线列表入口遵循同一图变更契约。当前采用带电拒绝编辑并提示先断电；不自动替学员断电或接线。
- 实体外壳同时阻止悬停和按下/点击穿透到被遮挡插孔/导线；用于诊断/测试的投影坐标采用实际 GLB 锚点与相同可视限位。窗口/分栏改变后须等实际尺寸与渲染尺寸同步再使用投影坐标，不能用旧坐标或固定等待时间掩盖竞态。
- 验收与开发入口分开：已核对当前开发机为 i5-12450H / RTX 4050，不是 PRD NFR-02 的 GTX 1650 级或 UHD 类核显目标机。用户已要求继续实现；本地场景与画质功能可用后允许推进 T0.9 内存态接线，不必因目标硬件未到位停工，但 T0.8 不得仅凭当前机测试勾选完成，原 1080p ≥30 FPS 等指标不变。
- 本轮完整回归：`pnpm test` 256/256（29 文件，含金标准）、`pnpm e2e` 18/18；连续 20 步撤销重做、21 根合批选线、带电拒绝编辑、重复连接拒绝、画布外释放/失焦取消、画质持久化和分栏改变后的真实尺寸同步均通过。接线验收截图为 `assets/generated/wired-bench.png`，T0.9 已完成。三档 12 s 主动相机操作重测（i5-12450H / RTX 4050，1920×1080 CSS 视口，3D 画布约 1918×933）为高/中/低 164.6/164.6/163.6 FPS、P95 均 6.2 ms、最大 64/64/63 draws、21,992/21,992/21,990 tris；报告为 `assets/generated/scene-performance.json`。这些是本机数据，不代表 GTX 1650 级或核显基线通过，T0.8 仍待目标机验收。

## 13. 安全与打包

- `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`；CSP 只允许 `self` 与 `blob:`/`data:`（3D 纹理）；拦截一切外网请求（`session.webRequest` 拒绝非 `file:`/自定义协议），满足 NFR-09 离线。
- electron-builder NSIS；`resources/ngspice`、`resources/content` 作为 `extraResources`；ngspice DLL 不进 asar。
- 关于页列出实际分发的第三方许可证（ngspice、字体、HDRI 及已采用的模型/材质），与 `assets/LICENSES.csv` 和随包声明一致；旧 KiCad 归档不随包分发，不因目录存在而宣称采用了其模型。
