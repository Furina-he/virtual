## 3. 核心数据模型

全部以 zod schema 定义在 `src/shared/schema/`，schema 是数据契约的唯一来源。下面是骨架，实现时补全字段。

### 3.1 模块（实训挂箱）`module.json`

```ts
Module = {

  name: string
  form: "box" | "board"         // 挂箱或实验板，挂载位置仍由项目 SLOT_ 配置决定

  netlist: string               // module.cir，.subckt 端口名 = jackId

  controls: {                   // 台面可调件（BEN-08），对应 GLB 中 KNOB_/SW_ 锚点
    id: string; label?: string; kind: "pot" | "switch" | "rotary" | "resistorBox"
    param: string               // 网表中的 .param 名
    range?: [number, number]; step?: number; steps?: number[]; stepLabels?: string[]
    targets?: { element: string; scale?: number; offset?: number; min?: number; values?: number[] }[]
    unit: string; default: number
  }[]
  indicators: (
    { id: string; kind: "led" | "lamp" | "motor"; probe: string }
    | { id: string; kind: "segment7"; label?: string; segments?: [string, string, string, string, string, string, string]; common?: string; threshold?: number; probe?: string }
    | { id: string; kind: "speaker"; between: [string, string]; audio: { fullScale: number } }
```

T0.15/B 公共模块契约：`label`/`stepLabels` 只表达内容定义的控件文案，`targets` 声明本模块实际电阻及有限正阻值换算，不执行任意公式或猜测网表目标。`simulation` 决定模块是否需要连续瞬态和步长硬上限；扬声器用实际插孔对生成固定探针，不能执行任意 `probe` 字符串。公共代码独立提交为 `65f9575`，同步差分记录及正反来源去重分别为 `2344cef`、`e54b210`，原生载入/声音订阅及重放门禁修订为 `701033f`；完整接口和跨 Worktree 互斥约定见 `docs/公共模块运行接口.md`，不在公共提交中夹带 MD-03/SD-22 内容或资产。

### 3.3 项目 `project.json`

```ts
Project = {
  id: "DG-01"; group: string; title: string; type: "basic" | "integrated"
  modules: { instanceId: string; moduleId: string; slot: string }[]   // 启动时自动挂载（BEN-04）
  allowedInstruments: string[]                                        // 仪表柜内容
  reference: {
    nets: string[][]            // 参考拓扑：每组为同一网络的插孔全局 ID

      quantity?: "mean" | "vpp" | "min" | "max" | "frequency" | "period"  // 仅波形，缺省 vpp
      minCycles?: number       // 仅波形，整数 >=2；频率/周期记录默认至少2个完整有效周期
      between?: [string, string]; branch?: [string, string]
    }[]

  dataTables: { id: string; columns: Column[]; rows: number; sanity?: SanityRule[] }[]
```

T0.15/A 内容与记录基线：`mode` 防止把交流档读数记录到直流测量点；步骤 `measurePoints` 显式指定当前需要的仪表位置，空数组只检查电路拓扑，缺省仍沿用项目的全部测量点，原接线检查器不放宽。非空测量点列表的步骤须有当前真实仪表读数才能完成，`expect` 如有则额外核对区间；`checkWiring` 要求当前接线报告通过，`recordTable` 要求指定表有完整记录行。新增字段与列/测量点、合理性规则/列、区间上下限的引用均由 schema 校验。

快捷记录只从当前非预检仿真作业及同步读数通道取数，不能把新拼装的计划与旧 UI 读数混用。纯 TS `domain/task/` 按当前电气网络、档位和仪表位置匹配测量点，保留表屏符号并按项目参考方向换算记录值，反接须明确提示；多台仪表匹配时要求选择来源。表格存有限数值或 null，支持手填与内容定义的合理性提示，不把理论值或内部未接表探针填入表格。该切片只交付直流项目基线，不代替 T1.5 完整引导/自主模式、T1.6 曲线/PDF 或 T1.7 存档。

DG-05 单表内容契约：一块固定毫安表选 20 mA 档（10 Ω），依次串入三个电流插座；电压测量前移除毫安表的两根线，使插座闭合，10 MΩ 电压表按 2 V / 20 V / 2 V 测 F→A、A→D、D→E。`kirchhoff` 表为一行六列，电流存 A、电压存 V；典型显示 +1.91 / −5.95 / +7.84 mA 与 0.982 / 4.04 / 0.982 V，分次状态的记录 KCL 残差为 +0.02 mA、KVL 电压和为 6.004 V，不能改填精确零残差。原三表金标准与新单表金标准独立保留；理论值只用于校核，不进入运行时记录。九步中的测量步骤要求实际仪表证据，最后分析步骤要求完整表行；手填合法数据仍被允许，不把快捷记录来源作为自动评分。

T0.15/B 阶段记录与计算：`Column.captureSteps?: string[]` 限制自动记录阶段，`Step.dataTable?: string` 指定本步骤关联表；一次记录只取一个当前会话快照、逐列禁用自动推进，最后至多完成一个匹配的当前测量步骤。MD-03 空载/带载同测 Uo，必须由两个阶段分别写列，不能遍历同口列同时覆盖。`computed` 只允许同一行列名、数值常量、括号和 `+ - * /`，依赖缺失、零分母、循环引用或非有限结果保持未完成并提示；不使用 `eval`，计算值不反馈驱动仿真。

公共接续拓扑：`Step.referenceNets`完整替换当前步骤默认网络，不与默认图合并，也不隐式继承前一步；缺省继续用项目默认网络。schema检验格式/重复归属，content:lint再检验实际插孔成员。命名模型库在构建期内联、传递依赖去重，跨模块同名同定义只保留一次，不一致即报错；领域层不读文件系统，拒绝路径/网络/.inc/.lib绕过。

公共多测量门禁：可选`Step.expects`逐项追加SI闭区间条件，与旧`expect`共同检查同一当前快照；引用计入测点scope和记录后推进，不替换现有条件。至少两个近期有效周期不能证明整个极值/均值窗已稳态，阈值/平台步骤需显式约束相应实测量。记录真实零值、手填与sanity提示语义不变，不将门禁变成自动评分或理论数据注入。

MD-03 内容契约：`amp1 / mod-analog-amp / SLOT_BOX_L1`，13 个顺序步骤、`static/gain/ri/ro/distortion` 五张表。静态记录实际 VCC、B/C/E，UCE 与 RC 压降法 IC 是带加载/分辨率边界的派生量；幅值增益为 Uo/Ui 的 Vpp 比，不硬填负号冒充相位。Ri 以已知 5.1 kΩ 和 Us/Ui 幅度估算；Ro 以 RL=2.4 kΩ 及空/带载两次 Uo/Ui 归一化比估算，保留示波器 1 MΩ 输入和输入随负载变化的影响。截止/饱和阶段记录 C 频率/Vpp 与真实同步 C−E 的最小/最大/均值；这些量来自学员的实际通道，不预填理论工作点或金标准波形。

确认重置还清空接线起点/终点选择器和未提交单元格草稿；项目切换恢复空记录，不能用撤销/重做复活上一项目。有效项目即使没有数据表也进入统一数据面板显示空状态，但快捷记录按钮仍禁用。模块配置加载失败时台面断电清空，显示中文重试/返回入口，不使用上一项目电路冒充新项目。

T0.8/T0.9 继续开发补充（2026-10-28）：

- 本轮场景来源为 `content/bench/scene.json`（`src/shared/schema/scene.ts` 的 `BenchScene`），只作场景/接线开发样例，不能当作已经完成 T0.15 的项目指导书/实验配置。插孔全局 ID 稳定采用 `dc1.*`、`ins-dc-power.*`、`ins-dc-voltmeter.*`、`ins-dc-ammeter.*`、`meter1.*`、`scope1.*`、`generator1.*`，不再使用随预览顺序变化的实例编号；项目差异仍放内容数据，不在代码中按项目 ID 分支。
- `pnpm assets:lint` 现在检查实际 `scene.json`：资产 ID、唯一实例、插槽存在/类型/占用、相对实训台的世界变换、固定仪表内容 ID 与 `fixedSlot`；预览预算也按该文件中的放置实例计算，不再只统计制作目录的旧预览表。通用 `content:lint` 保持独立，任意内容测试目录不强制依赖工作区资产目录。

## 4. 进程与通信

### 4.1 进程职责

| 进程 | 职责 | 禁止 |
|------|------|------|
| main | 窗口、IPC 路由、文件读写、PDF、启动/重启 sim 进程、撮合 MessagePort | 执行仿真、阻塞 I/O |
| preload | `contextBridge` 暴露 `window.api`，参数用 zod 校验 | 暴露 `ipcRenderer` 原对象 |
| sim (utilityProcess) | 加载 ngspice、维护仿真会话、按时间片推进、推送采样 | 访问文件系统中 `content/` 以外的路径 |
| renderer | UI、3D、波形、领域逻辑调用 | Node API（`nodeIntegration: false`、`sandbox: true`） |

### 4.2 通道

| 通道 | 方向 | 机制 | 内容 |
|------|------|------|------|
| 控制通道 | renderer ↔ main ↔ sim | `ipcRenderer.invoke` / `utilityProcess.postMessage` | 载入网表、上电/断电、改参数、开始/暂停 |
| 数据通道 | sim → renderer 直连 | main 用 `MessageChannelMain` 创建一对端口，分别交给 sim 和 renderer | 采样块 `{t0, dt, channels: Float32Array[]}`（transfer）、读数快照（10 Hz） |
| 事件通道 | sim → renderer | 同数据通道 | 不收敛、短路、过流、模型错误 |

渲染端：每个探针一个 `Float32Array` 环形缓冲（`renderer/lib/ring-buffer.ts`），`OscilloscopeScreen` 与 3D 屏幕纹理在 rAF / `useFrame` 中读取。高频数据不进 React state；读数快照以 10 Hz 写入 zustand 的 `readings` 切片。

T0.15/A 会话生命周期补充：`loaded` 先清空已持有缓冲，再释放上一会话的探针缓存，新会话通过 `buffer(id)` 获得新缓冲；消费者每帧重新取缓冲，不跨会话保留句柄。这样带修订号的瞬态仪表探针不会按每次重载累积 1 MiB 旧数组。有效逐块订阅跨载入保留，取消订阅后只移除空组，并用组身份校验避免旧取消函数删除新订阅。单元测试验证 48 次不同探针重载仅保留当前缓冲、64 个已取消订阅组均释放；这不是 4 小时 RSS/GC 验收的替代。

### 4.3 仿真会话协议

类型定义放在 `src/shared/ipc/sim.ts`，消息全部经 zod 校验。

```ts
// renderer → sim（经 main 转发的控制消息）
type SimCommand =
  | { type: "load"; requestId?: string; netlist: string; probes: Probe[]; analysis: Analysis; parameterTargets?: { param: string; elements: string[] }[] }
  | { type: "run" } | { type: "pause" } | { type: "stop" }
  | { type: "alter"; requestId?: string; changes: { param: string; value: number; targets?: { element: string; value: number }[] }[] }
  | { type: "setPacing"; mode: "realtime" | "window"; windowSec?: number }

type Probe = { id: string; kind: "v" | "i"; node?: string; nodeRef?: string; source?: string }
type Analysis =
  | { kind: "op" }
  | { kind: "tran"; step: number; continuous: true }
  | { kind: "ac"; fStart: number; fStop: number; points: number }

// sim → renderer（数据端口直连）
type SimEvent =
  | { type: "loaded"; requestId?: string; vectors: string[] }
  | { type: "op"; values: Record<string, number> }                    // probeId → 值
  | { type: "altered"; requestId?: string; simTime: number; changes: { param: string; value: number; targets?: { element: string; value: number }[] }[] }
  | { type: "chunk"; t0: number; dt: number; data: Record<string, Float32Array> }
  | { type: "status"; state: "idle" | "running" | "paused" | "error"; simTime: number }
  | { type: "error"; code: "no-convergence" | "singular" | "model" | "crash"; message: string; detail?: string }
  | { type: "log"; line: string }
```

实现补充（T0.4）：`chunk` 带块序号 `seq`（每次 `loaded` 从 0 重新计）；新增 `readings` 事件承载 10 Hz 读数快照。Electron 的 `MessagePortMain` 只能转移端口、不能转移 ArrayBuffer，所以 sim→main 这一跳每块复制一次（约 8 KB），可接受。`contextBridge` 不能传 `MessagePort`，preload 用 `window.postMessage` 把端口交给页面，渲染端（含弹出窗口）用 `window.api.sim.requestPort()` 申请。

T0.15/B 生效确认：控制 IPC 返回仅表示接收，实际载入通过唯一 `load.requestId` 与原生 `loaded.requestId` 关联，旧队列确认不打开新作业的声音/采样门禁。改参记录权限必须等匹配 `requestId` 的 `altered` 和生效时刻之后的真实采样/读数。快速连续调节不允许旧确认解除新请求的待更新状态；失败要可见并停止错误作业。实际电阻目标受 `load.parameterTargets` 白名单约束，改参数保留采样会话/探针/RingBuffer，结构、接线、分析或节奏改变仍完整重载。

约定：`chunk` 中数组按 `transfer` 发送；一次 `load` 对应一个会话，新 `load` 自动结束旧会话；`error.message` 已是面向学员的中文提示（PRD 15.4），`detail` 为 ngspice 原文，只进日志页。

### 4.4 sim 进程崩溃

main 监听 `exit`，自动重启 sim 进程并重新下发当前网表（实测 0.6~0.7 s 恢复）；启动后 5 s 内连续崩溃 3 次则停止重启，避免坏网表死循环；渲染端状态栏显示"仿真已重启"。ngspice 内部错误通过回调转为事件，不抛到 JS 顶层。

## 5. 仿真

### 5.1 ngspice 集成

- 绑定的共享库函数：`ngSpice_Init`、`ngSpice_Circ`、`ngSpice_Command`、`ngSpice_running`、`ngGet_Vec_Info`、`ngSpice_AllVecs`，回调 `SendChar`、`SendStat`、`ControlledExit`、`SendData`、`BGThreadRunning`。
- ~~`SendData` 逐点回调累积成块~~（T0.4 实测否决）：逐点跨线程回调在 Electron 内只有约 2.7 万点/秒，20 μs 步长下仅 0.55 倍实时。改为**按 50 ms 时间片推进**：`stop when time > T` + `bg_resume`，每片结束后按偏移批量读取新增向量数据（`readVector(name, start)`），重采样到等间隔网格再发块；不受限时约 3 倍实时，时间片同时用于实时节奏控制。后台运行要出数据须注册 `SendInitData` 回调。`koffi.view` 在 Electron 内崩溃，不使用。
- 不能给 tran 设"无限长"终止时间：ngspice 按终止时间/步长预估内存，过大会使整个 DLL 退出。用 `.tran 10 1e6 0 <步长>`，实际步长由最大步长参数约束。
- 暂停、停止、重新载入、`alter` 都在时间片边界执行（最多晚 50 ms），不从 JS 线程调 `bg_halt`（可能与排队中的回调死锁，未验证）。
- 分发目录 `resources/ngspice/`，`spinit` 只加载 `analog.cm`、`digital.cm`、`spice2poly.cm`、`xtradev.cm`、`xtraevt.cm`；`table.cm` 为 GPLv2+，不分发（结论见 `resources/ngspice/LICENSE-NOTES.md`）。
- 共享库只通过环境变量 `SPICE_LIB_DIR` 找 `spinit`，加载 DLL 前由 `NgSpice.open(dir)` 设置；依赖的 `libomp140`、`sndfile`、`samplerate` 先于 `ngspice.dll` 预加载。官方 dll 包缺 `sndfile.dll`/`samplerate.dll`，取自同版本控制台包。
- 错误判定靠解析 ngspice 文本输出（Error/aborted 行）；`ControlledExit` 后 DLL 无法再初始化，只能重启 sim 进程（§4.4）。

### 5.2 网表拼装（`domain/circuit`）

1. 每个模块实例展开为 `X<instanceId> <端口节点...> <moduleSubckt>`，端口顺序 = module.json 中 `jacks` 顺序。
2. 每台仪表按当前档位由 `spiceTemplate` 生成等效电路（电压表 = 内阻 + 电压探针；电流表 = 内阻 + 0 V 电压源测流；电源 = 理想源 + 内阻 + 限流行为模型）。
3. 学员导线 + 模块内跳线用并查集合并插孔 → 节点名。接地参考：台面"地"插孔所在网络为节点 0；无地时自动加 1 GΩ 到地防浮空（SIM-12）。
4. 每个节点追加 1 TΩ 对地泄放电阻，避免未连接插孔导致矩阵奇异。**这两步是必做项，不能依赖 ngspice 报错**：T0.3 实测浮空电容、电流源灌电容、电感直跨电压源等情况 ngspice 经自动收敛辅助后会"成功"返回无意义数值，不报错。
5. 故障注入在此步改写网表（§8）。
6. 输出：网表文本 + 节点映射表（插孔 → 节点）+ 网络划分（供接线检查）+ 仪表实例后缀（拼探针向量名，如电流表 `vsense_<后缀>#branch`）。

补充约定（T0.5）：模块子电路端口顺序必须与 `jacks` 一致；同一铜箔网络上的插孔在子电路内用 1 μΩ 相连；控件写成全局 `.param p_<实例>_<参数>`，经子电路 `params:` 传入，用于初始值、保存与重启恢复；连续瞬态改参按 T0.15/B 的声明电阻目标直接更新，不再据此承诺 `alterparam + reset` 保持储能状态。没接线的仪表不进网表；故障只改写目标实例的子电路副本。

这一层是纯函数，金标准测试覆盖。

### 5.3 分析类型选择

| 场景 | 分析 | 说明 |
|------|------|------|
| 只有直流源、直流仪表 | `.op` | 改参数后重跑，目标 ≤ 0.5 s（NFR-02） |
| 交流电表/功率表读数 | 短时 `.tran` 若干周期后取有效值 | 不用 `.ac`，因为含非线性负载（灯、日光灯）时 `.ac` 不对 |
| 扫频（谐振曲线、幅频） | 学员逐点改频率测量，每点 `.tran`；"曲线"页可选 `.ac` 快速预览 | 数据表须来自学员测量 |
| 示波器、数字电路、振荡器 | 连续分片 `.tran`（§5.4） | — |

模块声明 `simulation.analysis="tran"` 时，即使只接直流仪表也使用连续瞬态；实际步长同时满足模块硬上限、信号源周期、示波器和声音采样限制。任一模块要求 realtime 或存在扬声器时，实时节奏优先于示波器窗口；仅无实时要求的纯放大器可按内容显式使用 window，不按项目编号分支。

### 5.4 连续运行与实时推进（SIM-06/11/13）

```text
上电 → 载入网表 → bg_run tran（步长满足模块/仪表/声音约束，终止时间 = 很大）
      ↓ 片结束回调 → 批量读取本片新增向量 → 分块推送（不注册逐点 SendData）
学员改模块参数 → 片间隙按声明目标直接 alter 电阻值 → bg_resume（连续瞬态不 reset；参数定义同步到重启网表）
学员改接线 → 已上电则拒绝并提示先断电（WIR-07）；断电修改后再上电，新 load 从 0 开始
```

- 内存：不重启 tran。每读出 5 万点用 `let v=v[末点]` 截断当前 plot 的全部向量（原地换缓冲，tran 写入指针不变）；载入和 reset 后执行 `esave none`；每片调用 `ngSpice_Command(NULL)` 释放命令控制结构；向量用 memcpy 读进复用缓冲，不用 `koffi.decode`。首片前不得 `delete all`，否则 `.save` 失效。实测 10 分钟 77~82 MB 平稳（改前约 1 GB）。
- 节奏控制：sim 进程比较仿真时间与墙钟时间，仿真快于实时就暂停（数码管、1 Hz 秒脉冲、电机按真实时间走），落后墙钟超过 1 s 放弃追赶；示波器"运行"状态下按时间窗口仿真，`rate = max(1, windowSec/0.1 s)`，即每 100 ms 至少推进一个窗口，不设窗口则不限速。不需等待时用 setImmediate（Windows 上 setTimeout 粒度约 15 ms）。实测 1 Hz 计数 60 次误差 0.06%。
- 音频（SIM-13，P1）：**采用"提取基频和包络 + OscillatorNode 合成"**（T0.6 结论）。基频和包络每 10 ms 提取一次，PeriodicWave 音色每 0.5 s 按实测谐波更新。理由：SD-22 在 1/44100 s 步长下只有 1.35~1.48 倍实时（i5-12450H），单核 CPU 约 70%，基线机余量更小，低于实时就断音；逐点播放有混叠（谐波外能量 −4.5 dB，抗混叠参照 −20.6 dB），过采样后又跟不上实时。合成方案音高误差中位 0.1 音分，与机器速度无关。AudioWorklet 逐点播放的原型保留，示波器波形仍来自仿真。人工试听结论（2026-11-23，基于 `cb4a77d` 正式录屏/实播）：SD-22 救护车双音交替与消防车连续滑音人工听感正常，确认采用合成方案，T0.6 音频验收关闭。
- PCM 原型的离线校验先送入所有采样，再等待同一 Worklet 端口的统计回复作 FIFO 入队确认，之后才 `startRendering()`；否则离线渲染可能先于异步采样入队而得到全静音或截短尾部。该确认不改变实时播放、预缓冲、欠载统计或既有误差阈值；真实 Worklet 4 s 信号复测 64/64 完整，最大逐点误差 5.96e-8 V。历史实时欠载仍单独观察。
- 不收敛：应用层分类返回 ngspice 错误，停止测量/声音并提示检查接线；目前不自动修改 `gmin/reltol`。后续应用层容差或重试策略须先审批与回归，不改变 ngspice 自身默认内部求解策略。

T0.15/B 连续性验证边界：被修改 RC 支路的独立分段解析解发现旧 `alterparam + reset` 虽保留时间/块序号，却丢失该支路电容当前状态，误差约 1.79 V；原 0.02 V 门槛没有修改。声明实际正电阻目标后直接 `alter r.x<实例>.<元件>=值`、不 `reset`，再验证被改支路、源绝对相位、序号/时间、开关和目标白名单；MD-03 RW/KCE 的实际操作也验证会话不重载。这不能扩张为任意模型参数、改变电容值或改拓扑都能连续。

公共声音生命周期：主工作台只有一个声音生产者，弹出仪表窗口不重复发声；每次异步创建/等待都核对作业与资源代号。新组可以预先创建，但仅在所有输出 ready 且自身实际 `loaded` 匹配后调用 `activate()` 订阅，再发送 pacing/run；RMS 同样拒收旧载入尾片。原提前订阅会混入旧 t≈10 s 数据，使新 t=0 会话音色追踪失效，现以真实载入门禁修复，重复原生 loaded 也释放/重建时间基准；若重复载入发生在 pacing 异步等待期间，run 前仍须再次等待当前声音组 ready 并核对其身份。断电、重置、换项目、错误或销毁时先解除逐块订阅，再静音/停止并关闭旧 context；晚到的创建结果立即释放，真正的参数 alter 不重建追踪器。该公共接口不等于 SD-22 项目验收；SD-22 的实时与完整流程按 [SD-22 接口与验收](SD-22-接口与验收.md) 单独验收。

公共慢速状态提示：连续瞬态（`analysis.kind === 'tran'`）运行期间，纯 TS `domain/measurement/pace.ts`（`SimulationPaceMonitor`）根据实际收到的 `readings.simTime` 与单调墙钟计算最近 2.0 s 滑动窗的实际实时比（`ΔsimTime / ΔwallTime`）。连续观测满 1.5 s 后启用滞回判定：低于 `0.85×` 进入慢速告警，回升至 `≥0.92×` 解除；`loaded`、`altered`、暂停、断电、重置、错误或相邻读数间隔超过 3 s（如系统休眠恢复）时清空窗口。直流工作点（`.op`）不触发。运行状态写入独立低频 store（`stores/simulation-status.ts`），仅状态栏订阅，不引起主工作台或 3D 视口重渲染；正常实时运行时不额外推送更新，慢速状态下的倍率显示变化限流至 ≤2 Hz（500 ms），状态栏以图标、文字（`慢于实时（0.xx×）`）和 Tooltip 提示，不按项目编号分支，也不改变 ngspice、步长、节奏、缓冲或性能验收门槛，不视作性能修复。

### 5.5 器件模型库（WP-MODEL）

- `content/models/spice/` 下按类别分文件：`diodes.lib`、`bjt.lib`、`fet.lib`、`thyristor.lib`、`opamp.lib`、`regulators.lib`、`ttl.lib`、`cmos.lib`、`timers.lib`（NE555）、`behavioral.lib`（白炽灯、日光灯、气敏、话筒、电池、电机、晶振行为模型）。

T0.8/T0.9 本轮实现补充（2026-10-28）：
- 三档画质沿用本地 GLB/HDRI/字体，通过阴影、分辨率和渲染开销形成实际差异，切换不能改变电路图。开发期分别记录三档的分辨率/DPR、冷启动、实际渲染统计与连续相机操作时的帧率；静止 `demand` 场景停止绘制不算“无限 FPS”或基线性能通过。
- 当前档位实参：高/中/低贴图最大边长 2048/1536/1024 px，接触阴影分辨率 1024/512/关闭，DPR 范围分别 `[1, 2]`/`[1, 1.5]`/`[1, 1]`（前两档为设备 DPR 上限，不强制倍数）。每个实例拥有克隆材质/纹理，降采样和释放不修改 `useGLTF` 缓存的共享资源；画质保存在本地设置，不进入电路历史。
- 导线几何计算置于纯 TS 的 `src/domain/wiring/cord.ts`，不引用 React、Electron 或 Three.js。接口为 `cordPoints(a: [number, number, number], b: [number, number, number], sag: number, segments = 32)`，单位米，输出含精确两端点的 `segments + 1` 个样点。一般情况在端点 XZ 水平跨度所在的竖直平面中求真悬链线，重力朝 -Y；不以 Bezier 或“斜直线 + 对称 cosh”假代两端不同高的悬链线。
- 悬链线的下垂参数取端点连线水平中点到曲线的垂直距离，数值范围与 `Wire.slack` 一致；非退化跨度使用有界二分求解，近竖直/重合端点退化成确定性的侧向小环，保证有限坐标与精确接头。渲染端负责插头朝向、叠插分离和台面/地面限位；数学函数不假装执行碰撞或导线物理仿真。
- 实际求解以 `q = D / (2a)` 为未知量，满足 `sag = hypot(D * sinh(q) / q, deltaY) * tanh(q / 2) / 2`，其中 `D` 为 XZ 水平跨度、`a` 为悬链线尺度；消去水平偏移后求此单调标量方程，并保留不同高端点必需的 `sinh` 项。水平跨度小于 1 μm 时走侧向退化曲线；样本段数允许 2~512，非有限输入报错。22 个测试已覆盖端点、重力方向、不同高真悬链线解析对照、采样密度、竖直/重合和单位边界。
- `PatchCord3D` 按上述样点分段插值生成管线，不用会越出采样包围范围的平滑样条。插头按法线轴向叠插并侧向分离；导线在桌面/地面及途经面板正面作可视限位；PE 导线为黄绿双色。20 根以内逐根渲染，超过 20 根按颜色合批，选中导线单独高亮；这些属于可视几何策略，不是电路拓扑或物理仿真。
- 鼠标拖出/释放到合法插孔才创建导线；Esc、无效区域释放、窗口失焦、取消或重复连接拒绝不得遗留草稿。键盘/接线列表入口遵循同一图变更契约。当前采用带电拒绝编辑并提示先断电；不自动替学员断电或接线。

### 10.3 相机、拾取与可读性约定（T0.16，2026-11-01 批准）

原则：3D 负责导航和空间感，接线和调节在正对设备、撑满视口的特写里做。参照 LVSIM-EMS、Multisim 和国内招标的写法：左键用于操作，滚轮缩放，右键旋转，可以聚焦接线端子。依据和实测数据见执行计划 T0.16。

**鼠标与键盘**：

| 输入 | 行为 |
|------|------|
| 左键点插孔 | 开始接线；接线中再点一个插孔完成。也可以按住拖到目标插孔松开。只有设备上相邻插孔的屏幕间距 ≥14 px 时才直接拾取 |
| 左键单击设备 | 该设备插孔还太密（间距 <14 px）时，单击进入特写，不开始接线 |
| 左键拖空白处 | 平移，不旋转 |
| 右键拖动 | 受限旋转：水平方向 ±45°（相对正面），极角 0.08 rad~90°（从正上方算起，俯视预设约 8.6°）；目标点限制在台子包围盒内 |
| 中键拖动 | 平移 |
| 滚轮 | 朝光标缩放（`dollyToCursor`）；悬停在 3D 旋钮上时改为逐档调节旋钮 |
| 双击设备 | 进入该设备的正对特写（按包围盒正对 +Z 计算距离，四周留边）；双击的第一下若刚开始接线，会撤回这次待接线 |
| Esc | 接线中先取消接线；没有接线时从特写退回全景 |
| Home | 回全景 |

**视距与预设**：保留操作视角、正视、俯视三个预设，另加每个挂载模块和仪表的特写预设，在视口工具栏的“聚焦设备”下拉里选。默认操作视角仍用场景配置的相机：台面安装位必须在全景里可见，学员才能拖入仪表，所以不再按挂载设备收紧。特写时相机正对设备法线，四周留约 8% 边距。所有相机过渡都走 `CameraControls` 自带过渡，系统开启减少动态效果时取消过渡。

**接线时的相机**：只有左键正按住拖线时暂停相机的左键操作；等待第二个插孔时，缩放、平移、旋转、单击/双击和下拉聚焦都照常可用，线头一直跟着光标。跨设备接线就是在起点设备特写里点起点，换到终点设备特写再点终点。

**屏幕空间拾取**：插孔不再依赖世界坐标里的小球命中。每次指针移动，取可拾取设备上已投影、朝向相机的插孔中距指针 24 CSS px 以内最近的一个（只对最近 4 个做遮挡射线）；悬停目标切换时加 4 px 滞后，防止在两个插孔之间来回跳。导线按屏幕投影后的折线算距离，8 px 内可选中。被设备外壳挡住的插孔和导线不参与拾取。光标在插孔、导线、控件上为 `pointer`，左键拖空白处为 `grabbing`，指在插孔太密的设备上为 `zoom-in`。悬停、视角预设是瞬态状态（`three/bench-view.ts`），不进撤销历史。

**辅助（P1）**：
- 特写标签：光标 64 px 内、所在设备插孔间距 ≥28 px 时，最多给最近 4 个插孔叠加屏幕标签（`<Html>`，12 px），悬停插孔仍用完整提示。
- 导线右键菜单：右键单击（没有拖动）导线弹出 shadcn `DropdownMenu`，可改色、改垂度、删除；带电时禁用，接线中不弹出。
- 参考接线：视口工具栏“参考接线”开关，把当前步骤参考网络里还没连通的连接画成主题色虚线；缺失连接由 `domain/wiring-check/guide.ts` 按并查集计算，每个网络 N 个已连通组给 N−1 条（PRD WIR-08 的显示部分，引导/自主模式切换仍属 T1.5）。
- 聚焦仪表时底栏对应 2D 面板加描边并滚入视野。
- 顶栏“专注台面”一键收起或恢复三栏；默认左栏 18%、底栏 28%。首次进入视口左上角显示三步提示，卡片不拦截指针，关闭后记入 `localStorage`。
- 丝印电阻值统一写作“510 Ω”“1 kΩ”，与 SD-22 一致。

**渲染**：
- 面板贴图开启各向异性过滤，取 `renderer.capabilities.getMaxAnisotropy()`。
- 色调映射用 `NeutralToneMapping`，让面板接近设计色。
- 接触阴影放在台面高度（`workSurface.max[1]`），台式仪表才落在阴影上。
- 不加后期，遵守 PRD 15.2。
