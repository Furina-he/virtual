## 架构闸门与优先级

恢复原生取证前先收口文档一致性与交付门禁，任务见本页入口。该治理任务不扩展 M1/M2 或改变原生/教学验收门槛。

1. **优先处理正式电路实时根因**：现有原生观察段约占 Node 分段诊断 98%，读取/IPC 微调没有证据支持所需 5–7 倍提升。先审批官方同版 ngspice 47 的开发期保语义原生归因输入、工具链与许可；缺少精确构建输入时只报告预检，不自动安装或替换生产 DLL。依据 [联合仿真性能诊断](联合仿真性能诊断.md)。
2. **补齐应用出口**：正式两模式实时、原 15 s 周期门禁、17 步/6 表真实录屏、同一完整 0.2 s CV 平台窗及联合完整回归。`windowSec` 接口已经实现，但应用流程尚未走到合格平台步骤；不能将接口测试写成验收通过。
3. **慢速状态不得误导用户**：当前缺少实际墙钟/实时比的公共慢速告警，列为开放项；先明确低频公共状态契约，不按 SD-22 编号做特例，也不把告警补齐称为性能修复。
4. **外部与正式验收**：T0.0 原型/参数确认、T0.6 人工听感、T0.8 GTX 1650 级/核显与冷启动、T0.11 正式直流内容、MD-03 器材/参数，以及 M3 长期稳定性、恢复接线和干净断网安装保持开放。

禁止静默更改 RC/模型方程、2 µs 上限、物理误差、8 s/15 s 等验收窗口、0.2 s 平台要求、原始缓冲预算或 PCM 阈值；禁止另起加速声音流、手填/跳步骤冒充实测。任何必要方案变更先报告、审批、更新设计再实现。
